# تشخيص فشل workflow «publish» (commit c372b5f)

## الخلاصة
الفشل **ليس من الكود ولا من ملف الـ workflow ولا من الأسرار المفقودة**. ميتا (Instagram Graph API) ترفض
أول طلب يرسله الناشر برسالة:

```
IG GET /me → 400: {"message":"API access blocked.","type":"OAuthException","code":200}
```

أي أن **وصول تطبيق ميتا/حساب انستقرام إلى الـ API محجوب من جهة ميتا**. الحل يتم من لوحة مطوري ميتا، لا من المستودع.

## الأدلة
| البند | القيمة |
|---|---|
| آخر تشغيل ناجح | 2026-10-25 16:20 UTC — «0 due item(s)» (لم يكن هناك شيء مستحق، فلم يُتصل بانستقرام أصلاً) |
| أول تشغيل فاشل | 2026-10-25 19:10 UTC (run 40224775324) — أول عنصر انستقرام مستحق فعلاً: `2026-10-25 Instagram Stories S01` |
| التشغيلات الفاشلة بعدها | 11 تشغيلاً متتالياً حتى 2026-10-27 16:14 UTC، كلها على نفس الـ commit c372b5f |
| الخطأ في كل تشغيل | `IG GET /me → 400 … "API access blocked." … code 200` |
| مكان الفشل | `publisher/post.mjs` ← `igMe()` في `publisher/lib/ig.mjs:20` (أول استدعاء قبل رفع أي صورة) |

- الأسرار موجودة: السجل يُظهر `INSTAGRAM_ACCESS_TOKEN: ***` (غير فارغ)، و`X_PAUSED: 1` (منصة X موقوفة عمداً فلا تُحاوَل).
- الـ commit الوحيد بعد آخر نشر ناجح (c372b5f) غيّر فقط مهلة اللحاق من 6 إلى 24 ساعة — لا علاقة له بالمصادقة.
- رمز الخطأ يفرّق بين الحالات: رمز منتهٍ/غير صالح يعطي `code 190` (جرّبت رمزاً غير صالح فرجع
  `Invalid OAuth access token … code 190`)، أما هنا فالرمز مقروء لكن الرد `code 200 / API access blocked`،
  وهذا يعني حجب صلاحية التطبيق/الحساب وليس انتهاء الرمز.
- الكود يعمل محلياً: `node publisher/post.mjs --list` و`node publisher/post.mjs --due` (تشغيل تجريبي) ينتهيان بـ exit 0.

## الأسباب المحتملة (من جهة ميتا)
1. تطبيق ميتا عليه **قيد/تقييد** (مراجعة سياسات، «Data Use Checkup» سنوي غير مكتمل، أو طلب **توثيق النشاط التجاري**).
2. التطبيق في وضع **Development** والحساب ليس ضمن أدوار التطبيق (Tester/Admin)، أو أُزيل منها.
3. حساب انستقرام نفسه عليه تقييد/مراجعة أمنية (تسجيل دخول مشبوه، تغيير كلمة المرور) ألغت إذن التطبيق.

## المطلوب من المالك
1. افتح https://developers.facebook.com/apps ← التطبيق المستخدم للنشر ← تحقّق من **التنبيهات أعلى لوحة التحكم**
   (App Review / Data Use Checkup / Business Verification) وأكمل المطلوب.
2. في **App Roles** تأكد أن حساب انستقرام الخاص بالنشر مضاف ومقبول كـ Tester أو أن التطبيق في وضع Live.
3. افتح تطبيق انستقرام ← الإعدادات ← «التطبيقات والمواقع» وتأكد أن التطبيق ما زال مرتبطاً، وراجع «حالة الحساب».
4. بعد رفع الحجب ولّد **رمز وصول جديداً** (Instagram Login) وحدّث السر `INSTAGRAM_ACCESS_TOKEN` في
   Settings ← Secrets and variables ← Actions.
5. تحقّق دون نشر: شغّل `node publisher/check.mjs` محلياً، أو workflow «publish» يدوياً بدون تفعيل `go`.

## ملاحظة بعد الإصلاح
الناشر يتخطّى أي عنصر تأخر أكثر من 24 ساعة (`skipped (>24h late)`) حتى لا يُغرق الحساب. العناصر التي فاتت أثناء
الحجب (مثل `S01` بتاريخ 2026-10-25 و`P02-IG` بتاريخ 2026-10-26) لن تُنشر تلقائياً؛ إن أردتها انشرها يدوياً من
Actions ← publish ← Run workflow مع `ref` (مثل `P02-IG`) وتفعيل `go`.

## لماذا لم يُعدَّل الكود
لا يوجد خلل في الكود أو الـ workflow يمكن إصلاحه من المستودع؛ أي تعديل (مثل تجاهل الخطأ) سيُخفي المشكلة فقط
ويجعل المنشورات تضيع بصمت.
